SurgeGuard

A real-time crowd-safety platform that turns ordinary cameras into an early warning system, and explains every warning it gives.

The problem

Crowd crushes rarely start with one moment. Density builds, movement slows, exits clog, and the people responsible for safety often can't see it happening until it's too late.

Most venues already have cameras. What they lack is something that watches every feed at once and says, early and in plain words, when a crowd is becoming unstable and why.

What it does

  • Detects and tracks people in live feeds from USB webcams, RTSP cameras, phones running DroidCam, or recorded clips.
  • Scores crowd stability from 0 to 100, weighing crowd density, movement suppression, exit congestion, opposing flow and how fast things are changing.
  • Explains every score: which measurement drove it, and by how much.
  • Turns the score into a status and plain guidance, such as "deploy security personnel to the congested area".
  • Sends warning and critical alerts to a phone app, where security staff acknowledge them, mark that they're responding, and resolve them.
  • Drives an alert light and buzzer that always show the site's current status.

How it's built

Five parts around one backend.

AI pipeline

YOLO detects people and ByteTrack follows them from frame to frame, GPU-accelerated. Density, flow and queue analysis feed the stability index.

Backend

FastAPI with operator sign-in, real-time WebSockets and persisted history through SQLAlchemy, with Alembic migrations.

Command Center

A React and TypeScript dashboard for the control room: the live stream, the stability index and what drives it, guidance, queues, a site-wide view and an event timeline.

Alert app

A phone-first web app for security staff. It reuses the Command Center's real-time client, so both stay in step with the backend.

Hardware

An Arduino Uno over USB serial. The backend decides what to show; the Arduino only displays it, so the logic lives in one place.

What I'd improve next

  • Keep the event timeline across restarts. Today it lives in memory; only aggregated history is saved.
  • Let operators acknowledge site-wide alerts individually, not only per camera.
  • Move from SQLite to PostgreSQL for larger deployments. Access already goes through SQLAlchemy, so it's a configuration change plus migrations.
